Mockito究极指南：从基础到生产实战

前言

Mockito是一款Java的Mock框架，用于创建模拟对象，替代真实的依赖组件，从而让你更专注于测试逻辑本身。

  • 官方网站
  • 官方文档

使用场景

  • 测试依赖对象的行为（如数据库、web服务、第三方API）
  • 隔离被测试代码和外部系统
  • 编写单元测试

Maven依赖

一般配合 junit 使用。

如果需要用到一些注解如@Mock、@Spy等，需要加入mockito-junit-jupiter的扩展，注意版本要与mockito-core一致。

注意： Spring Boot Test 默认集成了 Mockito，不需要重复引入。

核心功能

Mockito 按核心功能划分，有以下三个：

  • 创建 Mock 对象: 使用 Mockito.mock()方法创建模拟对象。
  • 打桩（Stubbing）: 预设方法返回值
  • 验证行为

¶Spy部分模拟

spy用于包装真实对象并选择性覆盖其方法行为，适用于需要保留部分真实逻辑的测试场景。
原理：

  • 通过动态代理包装真实对象，生成代理类。
  • 与mock的区别：mock对所有方法返回默认值（如null、0）、不执行真实逻辑；spy仅拦截显式配置的方法。

¶方法行为控制

    异常风险 高（若真实方法抛出异常，测试会中断） 低
    对象状态影响 可能会修改 Spy 对象内部状态 无状态影响

  • 使用doThrow抛出异常

¶参数匹配器

Mockito参数匹配器是用于单元测试中灵活处理方法参数的工具，通常在参数值未知、不重要或需满足复杂条件时使用。
作用：

  • 解耦具体参数值，避免硬编码参数值，使得测试更聚焦于行为而非数据细节。
  • 支持复杂验证逻辑，如验证方法是否以特定参数组合被调用。
    按用途可将参数匹配器分为三类：
类型 常用匹配器 使用场景 示例
通用匹配器 any(),any(Class) 匹配任意类型或特定类型 when(service.call(any(User.class))).thenReturn(true)
类型专用匹配器 anyInt(),anyString()等 匹配特定基础类型或集合 verify(list).add(anyString())
精确值匹配器 eq(),same() 匹配具体值或对象引用 when(map.put(eq(1), eq("key))).thenReturn("oldValue")

重点：所有参数必须统一使用匹配器
若一个参数使用匹配器，那么其余参数也必须使用匹配器，否则报错。

¶构造方法创建模拟对象

拦截被测试类内部通过new创建的对象，控制其行为和返回值。
当被测试代码执行 new Class() 时，隐式触发模拟逻辑，而非显式注入。
必须使用 try-with-resource 限定模拟范围，避免影响其他测试。
使用场景： 模拟数据库连接类的构造方法。

mock对象核心流程：从方法调用到返回值

当调用mock对象的方法时，即从方法调用到返回值，底层逻辑是怎么样的呢？
这就涉及到了动态代理拦截和行为预定义机制。
分为以下几个步骤：

  1. 生成动态代理类
  • 核心技术： Mockito使用ByteBuddy动态生成mock类的子类（代理类），重写所有非final方法。
  • 关键字段注入：生成的代理类包含一个MockMethodInterceptor的成员变量，用于存储拦截逻辑的处理器（MockHandlerImpl）。
  1. 方法调用拦截
    当调用mock对象的方法时：
    • 触发拦截器：代理类的方法从写代码会调用MockMethodIntercepor.intercept()，将控制权移交到MockHandlerImpl.handle()。
    • 构建调用上下文：
      • 创建Invocation对象，将方法名、参数、mock对象本身进行封装。
      • 检查是否有匹配的预定义行为。
  2. 返回值决策
    Mockito按优先级确定返回值：
    场景 返回值来源 说明
    显式打桩(when().thenReturn()) InvocationContainerImpl 从容器中匹配当前调用的方法，返回预设值或异常
    未打桩但调用真实方法 真实方法返回值 需通过Mockito.CALLS_REAL_METHODS策略启用
    默认情况 返回类型默认值 如：int返回0，对象返回null
  3. 验证阶段（verify()）
    • 记录调用：每次方法调用都会被记录到InvocationContainerImpl。
    • 匹配验证：verify()检查调用次数或参数是否符合预期，使用ArgumentMathcher匹配参数。

执行流程图如下：

graph TD
    A[调用 mock 对象方法] --> B[代理类重写方法]
    B --> C{是否已打桩?}
    C -- 是 --> D[返回预设值/异常]
    C -- 否 --> E{是否启用真实方法?}
    E -- 是 --> F[调用真实方法]
    E -- 否 --> G[返回类型默认值]
    F --> H[返回真实返回值]

总结

Mockito的作用在于简化测试，通过模拟、打桩、验证这三步，可以轻松隔离外部依赖。
无论新手还是“老手”，都建议多写单元测试，毕竟 Mockito 的设计十分简单易懂。
