1.mysql剖析之架构篇

前言

本文旨在总结MySQL8.0的架构图

mysql架构体系

官方mysql8.0的简易架构图，如下：

由上到下，mysql架构分为4层：

  1. 应用层/连接层
  2. 服务层
  3. 存储引擎层
  4. 系统文件层

应用层/连接层

提供了用于应用程序连接mysql服务的接口。

还提供多种适配多种语言的接口，如：Go、JDBC、Python等。

服务层

服务层也叫mysqld，是mysql架构中最核心的。

¶NoSQL 接口

mysq8.0开始支持NoSQL的文档存储，可以将JSON文旦存储在集合中，并使用CRUD操作对其进行管理。

NoSQL完全符合完整的ACID，即至此事务。

¶SQL 接口

用于接收用户的SQL命令，并返回操作结果。

¶解析器

解析器用于验证和解析SQL命令。

¶优化器

MySQL 优化器是数据库引擎的核心组件，负责将用户提交的 SQL 查询转换为高效的执行计划。它通过评估多种可能的执行路径，选择成本最低的方案，以最小化查询的响应时间和资源消耗。

¶缓存和缓冲区

MySQL 的缓存和缓冲区是其性能优化的核心机制，通过内存缓存减少磁盘 I/O 和重复计算，显著提升数据库的响应速度和吞吐量。

  • 查询缓存（Query Cache）

    • 注意：MySQL 8.0 已移除查询缓存。

  • InnoDB 缓冲池（Buffer Pool）

  • 日志缓冲区（Log Buffer）

  • 排序缓冲区（Sort Buffer）

  • Join 缓冲区（Join Buffer）

  • Key Buffer（MyISAM 专用）

  • 临时表缓存（Temporary Tables）

存储引擎层

  • mysql采用插件式的存储引擎，支持多种存储引擎（如InnoDB、MyISAM、Memory等）。
  • 存储引擎负责数据的存储和检索。

文件系统层

  • 数据文件（如表数据、索引文件）
  • 日志文件（如Redo、Undo、Binary、Error、一般查询、慢查询、DDL日志文件）
    • 重做日志（Redo Log）：
      • 记录事务操作，用于崩溃恢复。
    • 回滚日志（Undo Log）：
      • 记录事务回滚消息。
    • 二进制日志（Binary Log，binlog）：
      • 文件名如binlog.000001、binlog.000002。
      • 记录所有修改数据库的SQL语句或数据变更，用于主从复制和数据恢复。
      • 由参数log_bin控制是否启用。
    • 错误日志（Error Log）：
      • 默认文件名为hostname.err。
      • 记录MySQL启动、运行或停止时的错误消息。
    • 通用查询日志（General Query）：
      • 默认文件名为hostname.log。
      • 记录查询sql语句，对性能影响较大，需谨慎启用。
    • 慢查询日志（Slow Query）：
      • 默认文件名为hostname-slow.log。
      • 记录执行时间超过阈值的慢查询sql语句，由long_query_time控制。
    • DDL日志（DDL Log）：
      • 记录DDL语句，即数据库对象结构变更相关的元数据操作。
      • DDL日志是MySQL内部管理的，用户不应直接修改或删除。
      • 用于元数据崩溃恢复。
