Mapstruct大法：从凹到凸

前言

MapStruct 是一款基于编译期代码生成的 Java Bean 映射工具，相较于反射型框架（如 BeanUtils、ModelMapper），它在性能和类型安全方面具有显著优势。本文将系统性地介绍 MapStruct 的核心概念、使用技巧及最佳实践。

环境

  • mapstruct 1.6.3
  • mapstruct spring extension 2.0.0

适用场景

  • 需要高性能的复杂实体对象转换

  • 希望将转换 Mapper 交由 Spring 容器管理

  • 追求类型安全的编译期检查，避免运行时错误

¶空值检查策略

策略说明：

  • ON_IMPLICIT_CONVERSION（默认）：仅在需要类型转换时检查 null

  • ALWAYS：始终检查源数据是否为 null

  • NEVER：从不检查源数据是否为 null

¶空值忽略策略

策略说明：

  • SET_TO_NULL（默认）：源数据为 null 时，将目标数据设为 null

  • SET_TO_DEFAULT：源数据为 null 时，目标数据设为默认值（0、空字符串、新集合等）

  • IGNORE：源数据为 null 时，保留目标数据的原始值

¶反向映射

将正向的mapping，反过来，不用反过来重复写@Mapping。

注意：

  • @InheritInverseConfiguration最适合数据结构对称（仅仅是字段名不同）的转换。一旦涉及赋值逻辑（常量、表达式、复杂计算），它就会失效，此时需要你手动介入修正。
  • @InheritInverseConfiguration不能处理表达式之类的映射，需要手动覆盖。

¶未映射字段策略

策略选项：

  • IGNORE：忽略未映射字段（unmappedSourcePolicy 默认策略）

  • WARN：编译时警告（unmappedTargetPolicy 默认策略）

  • ERROR：编译失败，强制处理所有映射

¶Spring 集成

¶基础 Spring 集成

很简单，只要在Mapper上加上@Mapper(componentModel = "spring")即可，编译生成的类就会加上@Component。

¶Mapstruct spring extension

适用场景：仅适用于非业务对象的转换，且需要将转换过程完全交由 Spring 管理的场景。对于常规业务对象转换，建议使用基础 Spring 集成。

¶原理

将 Mapper 继承自 Spring 的 Converter 接口，使 Spring 能够自动将这些 Mapper 注册到 ConversionService 中，支持通过 conversionService.convert() 进行转换。

总结与建议

谨慎选择集成方式：

  • 对于常规业务对象转换，优先使用 @Mapper(componentModel = "spring") 基础集成

  • 仅在需要 Spring 自动类型转换（如 @Value、Controller 参数转换）时，才考虑使用 MapStruct Spring Extension

避免过度复杂化：

  • MapStruct Spring Extension 的配置相对复杂，集合转换需要处理 TypeDescriptor
  • Converter 接口仅支持两个类型间的转换，多类型转换需要多个文件

适用场景分析：

  • MapStruct 适合复杂对象间的高性能转换

  • MapStruct Spring Extension 自动转换适合简单对象的参数绑定

  • 两者结合时需权衡复杂度与收益，避免"杀鸡用牛刀"
