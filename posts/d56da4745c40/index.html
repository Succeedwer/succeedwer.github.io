gateway之大纲

Spring Cloud Gateway 结构图

¶核心架构层次

  1. 客户端层

    外部请求统一入口

  2. 网关核心层

    • Spring Cloud Gateway: 网关主体
    • Gateway Handler Mapping: 负责路由匹配，根据断言条件请求映射到对应路由
    • Gateway Web Handler: 请求处理入口点
    • Filtering Web Handler: 组织并执行过滤器链

  3. 路由配置层

    • 路由配置：路由规则定义中心

    • 静态路由(YAML)：通过配置文件定义的路由规则

    • 动态路由(API/DB)：通过API或数据库动态配置的路由规则

  4. 过滤器层

    • 过滤器链：请求/响应处理管道

    • GlobalFilter：全局过滤器，作用于所有路由（如认证、日志）

    • GatewayFilter：路由过滤器，仅作用于特定路由（如限流、重写路径）

  5. 服务发现层

    • 服务发现集成：与服务注册中心集成

    • Nacos/Eureka：服务注册与发现组件

    • LoadBalancer：负载均衡器，支持轮询、权重等策略

  6. 后端服务层

    • 目标服务：经过网关处理后的请求转发目标

    • 微服务集群：实际业务处理的后端微服务

¶核心功能

  1. 路由配置：支持静态（YAML）和动态（API/数据库）路由配置
  2. 断言匹配：基于路径、方法、Header、参数等条件进行路由匹配
  3. 过滤器链：提供全局过滤器和路由过滤器，支持认证、限流、日志等。
  4. 服务发现：集成Nacos/Eureka，自动发现服务实例
  5. 负载均衡：集成Spring Cloud LoadBalancer，支持多种负载均衡策略。
  6. 限流熔断：支持Redis令牌桶限流和Resilience4j熔断。

¶请求处理流程

  1. 客户端请求到 Spring Cloud Gateway
  2. Gateway Handler Mapping 进行路由匹配
  3. 匹配成功后，Gateway Web Handler 接管请求
  4. Filtering Web Handler 执行过滤器链的pre（前置处理）逻辑（身份认证、请求修改、参数校验、限流检查、日志记录）
  5. 通过负载均衡选择目标服务实例
  6. 请求转发到目标服务
  7. 服务处理完成后，执行过滤器链的post（后置处理）逻辑（响应修改、错误处理、性能监控、缓存处理、日志记录）
  8. 响应返回到客户端
